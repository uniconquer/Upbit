# 1분봉 모의 실험으로 전환 — 2026-09-06

현재 주력 관찰은 **1분봉**이다. 이전 일봉 상태와 결과는 그대로 보존한다.
실제 주문·계좌·API 키·기존 실거래 워커는 사용하거나 변경하지 않았다.

## 바뀐 동작

- 지표 기간의 단위가 분봉 개수로 바뀐다. 예를 들어 200 EMA는 200일이 아닌 200분봉 기준이다.
- 같은 날에도 각 분의 완료 봉으로 신규 신호를 처리한다. 같은 분 재실행은 중복 처리하지 않는다.
- 일일 손실 집계와 날짜 변경은 분봉 신호 처리와 별개로 유지한다.
- 과거 재생은 이전 봉 신호를 다음 봉 시가에 적용하고 체결 기록에도 실제 분봉 시각을 남긴다.
- 현재 관찰은 완료 봉과 관찰 시점 현재가를 사용한다. 미완성 봉은 계산에 넣지 않는다.
- 거래가 없어서 캔들이 없는 분은 직전 가격·거래량 0으로 채우며 해당 봉의 신규 매수는 막는다.
  미래 가격으로 과거 빈칸을 채우지 않는다.
- 현재 데이터는 캐시하고 이후에는 최근 구간만 갱신한다. 오래 끊기면 다시 수집한다.
- 24개 후보와 후보별 높은 비용 버전을 유지한다. 공격적인 가상 투자 비중 100% 후보도 포함된다.

## 첫 과거 재생

BTC·ETH·XRP 각각 5,000개 1분봉으로 24개 후보를 비교했다.
250개 준비 봉 이후, 앞 65% 구간 안에서만 설정을 선택하고 나머지 35%는 평가했다.
가상자금 100,000원, 편도 수수료 가정 0.05%, 편도 슬리피지 0.10%를 적용했다.
높은 비용 버전은 편도 슬리피지 0.30%다.

- 전체 입력: 2026-09-02 19:42 ~ 2026-09-06 07:01 UTC
- 평가 시작: 2026-09-05 01:52 UTC; 약 29시간의 평가
- 가장 높은 학습 점수도 음수여서 선택 규칙은 **현금 보유**를 택했다.
- 그 후보를 연구 목적으로 평가했을 때: 완료 매도 39회, 수익률 **-4.04%**, 승률 0%.
- 높은 비용 버전: 수익률 **-4.06%**. 비용과 손실 제한 때문에 체결 경로·거래 수가 다르다.

이는 분봉에서 사례를 빨리 모을 수 있음을 보여주지만 수익성이 좋아졌다는 결과는 아니다.
평가 구간이 짧고 동일 시장 흐름에 속한 거래가 많으므로 독립적인 장세 검증으로 볼 수 없다.
원본 CSV, 후보 설정, 학습 순위, 평가 결과는 `.runtime/minute-research-v1/`에 보존한다.
이 과거 기록은 미래 모의 관찰 수나 승격 조건에 포함하지 않는다.

## 현재 실행

`src.minute_learning --watch` 백그라운드 프로세스가 매 분 경계 직후 관찰한다.
컴퓨터가 켜져 있고 절전하지 않아야 한다. 프로세스는 Codex 대화가 끝나도 실행되지만,
PC가 꺼진 동안의 체결을 소급 생성하지 않는다. 앱의 매시간 예약은 프로세스 상태를
점검하고 의미 있는 변화 또는 오류만 알린다. 앱을 닫으면 이 상태 점검은 동작하지 않을 수 있다.

```powershell
# 현재 1분봉 시세로 1회 관찰
py -3 -m src.minute_learning

# 계속 관찰; 이미 실행 중이면 중복 프로세스 잠금이 시작을 거부한다
py -3 -m src.minute_learning --watch

# 별도 결과 폴더로 새로운 과거 실험
py -3 -m src.minute_learning --research --folder .runtime/minute-research-v2
```

`적응형 모의매매 → 자동 개선 실험`의 기본 주기가 1분봉으로 바뀌었다.
이전 일봉 기록도 선택해서 볼 수 있다. 1분봉 관찰 기록과 프로세스 상태는
`.runtime/minute-learning/state.json`, `worker.json`에 저장한다.

최소 30일·관찰 날짜 25일·관찰률 80% 및 비용·체결·낙폭 기준은 유지한다.
관찰률 분모는 시간 수 대신 분 수로 바꿨다. 빠른 거래 수집이 자동으로 승격·실전 승인을
뜻하지 않는다. 첫 세대 평가 예정은 충분한 관찰이 지속될 경우 10월 6일 이후다.
중지할 때는 백그라운드 프로세스와 이를 복구하는 매시간 점검 예약을 함께 중지해야 한다.

## 매일 구조 연구

`py -3 -m src.strategy_research_cycle`은 UTC 날짜별 한 번만 새 연구를 수행한다.
기본 10,000개 분봉에서 기존 기준 전략과 12개 조합을 비교한다. 조합은 완성된 5분/15분봉
추세, 비용 대비 변동 폭 필터, 3봉 청산 확인, 최소 손절 거리 0.6%/1.2%다.
새 필드의 기본값은 기존 후보의 동작과 식별자를 유지한다.

앞 65%에서 후보 하나를 선택한 뒤 뒤 35%와 높은 체결 비용으로 검증한다.
학습·검증 수익률이 양수이고 각각 완료 매도가 5회 이상이며, 높은 비용 수익률도 양수이고
검증 낙폭이 10% 이내여야 다음 모의 세대의 추천 목록에 들어간다.
현재 세대의 설정이나 잔고를 중간에 바꾸지 않으며, 다음 세대가 시작할 때 최대 4개 추천을
수용한다. 추천 출처와 세대 편입 기록을 보존한다. 대표 후보 승격에는 별도의 미래 관찰 기준이 적용된다.

매시간 앱 예약이 그날 연구 완료 여부를 확인해 실행한다. 날짜별 프로토콜과 원본 봉,
결과는 `.runtime/strategy-research/YYYY-MM-DD/`에 저장한다. 같은 날짜 재실행은 결과를 재사용한다.
반복 연구의 과거 구간은 서로 겹치므로 독립 검증 횟수로 세지 않는다.
자동화 범위는 검증된 규칙의 조합·평가이며 프로그램 소스를 임의로 다시 쓰거나 실거래에 배포하지 않는다.

2026-09-06 첫 구조 연구의 선택 후보는 검증 수익률 0%, 완료 매도 0회로 추천되지 않았다.
필터로 거래를 줄였다는 사실만으로 수익성이 좋아졌다고 해석하지 않는다.

## 이전 실험에서 배우는 탐색

다음 새 날짜의 연구부터 `research_search.py`가 24개 설정을 제안한다. 기존 13개 비교 기준,
이전 학습 결과 상위 후보 주변의 변형 최대 6개, 무작위 새 조합 최소 5개로 구성한다.
거래 5회 미만인 과거 후보는 부모로 쓰지 않는다. 쓸 만한 부모가 없으면 새 조합 탐색을 늘린다.
손실을 낸 부모도 상대적으로 나은 실험 방향으로 참고할 수 있지만 수익성이 입증된 후보로 취급하지 않는다.

최근 14개 연구의 **학습 점수만** 읽고 최종 검증 수익률은 제안에 사용하지 않는다.
과거 학습 구간이 이번 검증 구간을 침범하면 해당 기록은 제외한다. 날짜별 난수 시드와 후보의
부모·출처를 프로토콜에 저장하므로 재실행 결과를 재현할 수 있다. 기존 날짜의 완료 실험은 유지한다.
탐색 대상은 진입 방식, 추세 기간, 상위 봉, 비용 필터, 청산 확인과 손절 거리다.
투자 비중·손실 제한·수수료 가정은 탐색으로 유리하게 바꾸지 않는다.

이는 진화적 파라미터 탐색이다. 신경망을 학습하는 PPO/DQN 강화학습이나 Codex 모델 자체의
재학습은 아니다. 이전 경험이 다음 실험을 바꾸지만 성능 향상은 보장하지 않는다.
실제 개선 여부는 새 모의 관찰에서 확인해야 한다.

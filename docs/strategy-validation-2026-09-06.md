# 수익성 점검과 검증 경로 개선 — 2026-09-06

## 결론

현재 확인한 결과만으로 자동매매의 수익성을 입증할 수 없다. 실제 주문을 실행하거나
환경변수·기존 실행 중인 워커 설정을 변경하지 않았다. 수익 목표에 맞춰 거래 횟수나
투입 금액을 늘리는 대신, 부풀려진 백테스트를 제거하고 후보 검증 경로를 추가했다.

## 수정한 문제

- 공통 단일 종목 백테스트가 매도하지 않은 포지션의 손익을 무시했다.
  이제 매 봉의 순청산 추정액에 매수·매도 수수료와 슬리피지를 반영한다.
  100 → 50 → 110 가격 경로에서 최대낙폭이 기존 0% 대신 -50%로 계산된다.
- 매수·매도 신호가 같은 봉에 있으면 통계는 즉시 왕복매매하고 차트는 보유하는
  불일치가 있었다. 이제 통계와 차트가 동일한 상태 전이를 사용한다.
- 결측 신호가 거래를 만들거나 예외를 발생시키고, 결측 가격을 건너뛰면
  자산곡선의 날짜가 어긋날 수 있었다. 결측 신호는 거래하지 않고 날짜를 유지한다.
- `next_open` 체결 모드를 추가했다. 종가로 확정한 신호는 다음 봉 시가로 체결하며
  갭과 마지막 봉의 미체결 신호를 반영한다. 기존 UI·워커의 표시용 백테스트는
  호환성을 위해 `same_close` 기본값을 유지하므로 새 검증 결과와 같지 않다.

## 새 검증 도구

`src/strategy_validation.py`는 키·계좌·주문 API를 사용하지 않는다.
완료된 UTC 일봉만 수집하고 데이터를 CSV로 보관한다.
API의 일봉 기준과 페이지 이동은 [업비트 공식 문서](https://docs.upbit.com/kr/kr/reference/list-candles-days)를 따른다.

후보는 추세 돌파, EMA 눌림목, 상대강도 로테이션, 상대강도 가드의 기존 기본값 네 개로 고정했다.
먼저 학습 구간만 전달해 지표와 성과를 계산한다. 순수익률에서 최대낙폭 크기를 뺀
점수로 하나를 선택하고, 양의 점수 및 최소 거래 수를 만족하지 못하면 현금을 선택한다.
선택 후에만 이후 구간을 평가한다. 이후 구간 결과로 다른 후보를 다시 선택하지 않는다.
선택한 전략의 지표 초기화에는 과거 데이터를 유지하고, 테스트 시작 시 포지션은 비운다.
학습 마지막 종가 신호는 테스트 첫 시가에 체결할 수 있다.

기존 `strategy_lab.py`는 holdout 결과를 점수와 생존 후보 선택에 사용한다.
그 출력은 탐색 결과이며 독립적인 최종 검증 결과로 해석하면 안 된다.
기존 연구 기능 자체는 보존했고, 새로운 도구에서 별도의 선택·평가 경로를 제공한다.

```powershell
# 공개 시세로 새 평가 — 반복 평가에 사용한 기간은 더 이상 미지의 검증 구간이 아님
py -3 -m src.strategy_validation --output .runtime/validation-new

# 이번에 저장한 데이터만으로 재현 — 네트워크·주문 없음
py -3 -m src.strategy_validation --input-dir .runtime/validation-initial --output .runtime/validation-replay
```

## 최초 실행 결과

BTC·ETH·XRP 각각 1,000일, 종목별 초기 자본 1/3 고정, 종목 간 자금 이동 없음.
첫 150일은 지표 준비, 다음 450일은 후보 선택, 마지막 400일은 평가에 사용했다.
편도 수수료 가정 0.05%, 편도 슬리피지 가정 0.10%; 비용 스트레스는 슬리피지 0.30%.
수수료는 실제 계정의 계약 요율을 조회한 값이 아닌 검증 가정이다.

- 선택 구간: 2024-05-09 ~ 2025-08-01 UTC
- 평가 구간: 2025-08-02 ~ 2026-09-05 UTC
- 선택 전략: `relative_strength_guard`

| 평가 | 수익률 | 최대낙폭 | 완료 거래 |
|---|---:|---:|---:|
| 선택 전략 | +0.0112% | -8.5754% | 7 |
| 체결 비용 스트레스 | -1.1814% | -9.0432% | 7 |
| 같은 종목 단순 보유 | -38.4070% | -59.1805% | 0 |

보유 중인 포지션은 비용을 뺀 청산 추정액으로 평가하고 완료 거래 수에는 넣지 않는다.
보고서 상태는 `INSUFFICIENT_EVIDENCE`: 비용 스트레스에서 손실이며 완료 거래도 적다.
단순 보유보다 낙폭이 작았다는 사실이 향후 수익성을 입증하지는 않는다.
원본 수치와 입력 CSV는 `.runtime/validation-initial/`에 있다.

## 남은 검증 범위

이 결과는 실제 스캐너의 종목 선택·공유 자본·위험 한도·체결 지연을 재현하지 않는다.
일봉 종가 기준 최대낙폭은 장중 손실을 과소평가할 수 있다. 선택 종목과 기존 전략 개발에
과거 데이터가 활용됐을 가능성도 있어 완전히 새로운 미래 데이터 검증이 필요하다.
현재 UI와 워커는 마지막 캔들로 신호를 판단하는 경로가 있어 미완성 봉 처리도 별도 점검 대상이다.
새 평가 도구는 일봉 완료 여부를 확인하지만 기존 실시간 경로를 바꾸지는 않았다.

다음 실험은 평가 기간에 맞춰 파라미터를 재조정하는 것이 아니라, 후보와 위험 한도를
먼저 고정한 다음 새로운 기간의 모의매매에서 실제 비용·중복 주문·보유 종목 청산을
검증하는 것이다. `PAPER_CANDIDATE`가 나오더라도 실거래 승인이나 수익 보장을 뜻하지 않는다.
